# Mobile Easy Use SDK 原则

- SDK 的首要目标是方便 Agent 识别能力并生成简单、准确、可运行的代码。
- Android 与 iOS 应按各自平台特性设计；允许 API、参数、返回值和能力边界不同，不为形式统一而增加抽象。
- 平台差异应在命名、类型、文档、示例和不支持项中明确呈现，避免 Agent 根据相似方法名作错误推断。
- 每个平台应保持清晰、稳定、易发现的入口和唯一的方法描述真源，并为方法提供简短用途、参数约束、返回结构及最小示例。
- 只复用语义和实现都稳定一致、且不会增加 Agent 使用复杂度的基础设施；当前 `runtime` 的 RPC、模块加载和函数调用逻辑适合双端共用。
- UI、输入、等待、证据等平台能力默认独立实现；相似的信息结构可以保留，但不以抽取公共代码为目标。
- 优化设计时优先判断：它是否能让 Agent 更容易选对 API、填对参数并生成可直接运行的代码。

## 线程契约

- SDK 公开 API 默认支持从任意线程调用。
- SDK 实现负责所需的平台线程调度。
- 无法消除的调用线程限制必须写入对应 `.d.ts`。
