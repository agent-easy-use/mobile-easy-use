# Mobile Easy Use

**أداة لمطوري Android وiOS تمنح وكلاء الذكاء الاصطناعي وصولًا إلى وقت التشغيل لاستكشاف التطبيقات وتصحيحها وتنفيذ اختبارات واجهة آلية.**

الوثائق: [English](../README.md) · [简体中文](./README.zh.md) · [Français](./README.fr.md) · [Русский](./README.ru.md) · [Español](./README.es.md) · **العربية**

مقارنة بتطوير الويب، يصعب الوصول مباشرة إلى البيانات الداخلية وحالة الأعمال ومسار التنفيذ في تطبيقات الهاتف. **«نجح طلب البيانات، فلماذا لم تُحدّث القائمة؟»** تعتمد مثل هذه المشكلات على البيانات والحالة وتوقيت التنفيذ الفعلي على الجهاز، وهي أمور لا يكفي تحليل الشفرة الساكن وحده لتفسيرها غالبًا.

يمنح Mobile Easy Use وكلاء الذكاء الاصطناعي وصولًا إلى بيئة تشغيل التطبيق عبر MCP. وبذلك يستطيع الوكيل ربط الشفرة المصدرية بالسلوك الفعلي، وقراءة الكائنات والحالة، واعتراض استدعاءات الدوال، وتغيير ظروف التشغيل مؤقتًا، والتفاعل مع الواجهة وفحصها.

## استكشاف حالة التطبيق وسلوكه

توجّه ملاحظات التشغيل الوكيل خلال دورة التطوير:

- **البحث وقبل البرمجة**: ربط الشفرة بالاستدعاءات والبيانات والحالة داخل التطبيق أثناء تشغيله لفهم سلوكه الفعلي.
- **التحقق من الحل التقني**: تعديل الإعدادات أو الحقول أو القيم المعادة مؤقتًا داخل التطبيق أثناء تشغيله، واختبار الافتراضات ثم استعادة القيم الأصلية.
- **تحديد المشكلة**: إعادة إنتاج المشكلة في التطبيق وربط الاستدعاءات الفعلية وتغيّرات الحالة وسلوك الواجهة لتحديد موضع الخلل.
- **بعد تعديل الشفرة**: تشغيل التطبيق المعدّل وإعادة السيناريو للتحقق من النتيجة الفعلية. يمكن تحويل التوقعات المؤكدة إلى اختبارات انحدار.

مثلًا، اطلب من الوكيل:

```text
افحص هذه الصفحة التي يتحكم بها إعداد: تحقق من قيمته ومسار التنفيذ الفعلي،
ثم غيّره مؤقتًا وافحص البيانات والواجهة في الحالتين. استعد القيمة الأصلية بعد الانتهاء.
قيّم الحل بناءً على الأدلة وحدد ما لم يُتحقق منه بعد.
```

يمكن للوكيل استكشاف المعلومات التالية، بحسب المنصة وطريقة تنفيذ التطبيق:

| معلومات وقت التشغيل | ما الذي توضحه |
| --- | --- |
| كائنات الأعمال والحالة | البيانات الحالية وذاكرة التخزين المؤقت والإعدادات والتغيّرات بعد الإجراء |
| استدعاءات الدوال | الدوال المنفذة ومعاملاتها ونتائجها ومكدسات الاستدعاء ومسارات التنفيذ |
| زمن التنفيذ وتغيّر الذاكرة | مدة تنفيذ الدوال وتغيّر ذاكرة العملية |
| سجلات الأعمال | المرحلة التي وصل إليها التنفيذ والمؤشرات المرتبطة بالفشل |
| حالة الواجهة وعناصر التحكم | وجود العناصر وظهورها وموضعها وخصائصها |
| لقطات الشاشة والعناصر | المظهر الفعلي والتغيّرات المرئية بعد الإجراء |

## اختبارات واجهة آلية محسّنة

إلى جانب إجراءات الواجهة والتحقق من اللقطات، تحقّق مباشرةً من حالة الأعمال الداخلية، وغيّر سلوك التشغيل مؤقتًا لإعداد السيناريوهات، وحلّل الاستدعاءات الفعلية وتغيّرات الحالة لتحديد أسباب الفشل.

1. **تحققات أعمق**: افحص الواجهة واللقطات وحالة الأعمال الداخلية معًا. بعد تحديث قائمة، تحقّق من المحتوى المعروض والبيانات الداخلية وذاكرة التخزين المؤقت.
2. **تحكم أكبر في السيناريوهات**: استبدل الحقول أو القيم المعادة مؤقتًا لاختبار البيانات الفارغة أو الفشل أو فروع إعدادات محددة.
3. **تفسير أوضح للفشل**: اربط الاستدعاءات الفعلية ومعاملاتها ونتائجها وتغيّرات الحالة. إذا لم تتحدّث القائمة، حدّد ما إذا كانت البيانات لم تُحفظ أم أن الواجهة لم تتحدّث.

### مثال: نقرة واحدة وثلاثة مستويات من التحقق

في الحالة الأولية لصفحة **UI → Class names and subclasses** في Android ApiDemo، يجب أن تضبط نقرة `FIRST` العداد على 1 وتعرض `FIRST:1`. قبل كل تشغيل، افتح الصفحة بحالتها الأولية وجهّز لقطة مرجعية مراجَعة لما بعد النقرة في `baselines/first-clicked.jpg`، بمسار نسبي إلى ملف الاختبار.

تتضمن [اختبارات Android](../fixtures/android/ApiDemo/tests/) و[iOS](../fixtures/ios/ApiDemo/tests/) سيناريوهات كاملة مع استعادة الحالة. لمقارنة النافذة استخدم `expect().toHaveWindowScreenShot(...)`.

```javascript
const { describe, test, expect, run } = Test.create();
export { run };

describe('Counter button', () => {
  test('updates state, UI, and appearance', async () => {
    const button = R.id.api_ui_class_first;
    const clicked = await AndroidExp.runOnMainThread(() => AndroidExp.input.click(button));
    expect(clicked.ok).toBe(true);

    // حالة الواجهة
    await expect(button).toBeVisible();
    await expect(button).toSatisfy(view => String(view.getText()) === 'FIRST:1');

    // لقطة الشاشة
    await expect(button).toHaveElementScreenShot('baselines/first-clicked.jpg');

    // حالة الأعمال الداخلية
    const count = await AndroidExp.runOnMainThread(() => Java.use(
      'com.agenteasyuse.mobileeasyuse.apidemo.state.ApiDemoState'
    ).getInstance().getClickCount());
    expect(Number(count)).toBe(1);
  });
});
```

## البدء

يتطلب Node.js 20 أو أحدث. يحتاج Android إلى ADB وجهاز أو محاكي، بينما يحتاج iOS إلى macOS وXcode وأدوات سطر الأوامر. ويتطلب الجهاز الفعلي أيضًا `iproxy` وتوقيع XCTest Runner.

### 1. تثبيت Skills

نفّذ الأمر من جذر مشروع التطبيق:

```bash
npx skills add agent-easy-use/mobile-easy-use --skill '*'
```

### 2. دمج Mobile Easy Use

اطلب من الوكيل استخدام `to-android-integrate` أو `to-ios-integrate`. يقوم Skill بتنزيل ملفات الإصدار والتحقق منها، وتهيئة مشروع debug، وإرجاع إصدار MCP المتوافق. بعد ذلك ابنِ هذا الإصدار وثبّته على الجهاز المستهدف.

### 3. إعداد MCP

استخدم الإصدار نفسه الذي أعاده Integrate؛ الإصدار `0.1.0` أدناه مجرد مثال:

```json
{
  "mcpServers": {
    "mobile-easy-use": {
      "command": "npx",
      "args": ["-y", "@agent-easy-use/mobile-easy-use@0.1.0"]
    }
  }
}
```

اضبط مجلد عمل MCP على جذر المشروع المستهدف، ثم أعد تحميل الإعدادات وتحقق من ظهور `get_sdk_declarations` و`connect`.

### 4. الاستكشاف أو الاختبار

بعد بناء التطبيق المدمج وتثبيته، اطلب من الوكيل استخدام `to-android-probe` أو `to-ios-probe` واشرح المشكلة بلغة طبيعية. يجمع Probe بين الشفرة المصدرية وPresets وملاحظات وقت التشغيل لتنفيذ الاستقصاء وتحليل الأدلة.

أنشئ الاختبارات باستخدام [to-android-test-script](../skills/to-android-test-script/SKILL.md) أو [to-ios-test-script](../skills/to-ios-test-script/SKILL.md). شغّل الملفات الموجودة ولخّص النتائج باستخدام [to-android-test](../skills/to-android-test/SKILL.md) أو [to-ios-test](../skills/to-ios-test/SKILL.md).

```text
أنشئ اختبارات لتحديث القائمة تتحقق من الواجهة واللقطات والبيانات الداخلية.
شغّل مجلد tests ولخّص الحالات الناجحة والفاشلة والتي لم تُنفّذ.
```

## دليل Skills

| الإمكانية | متى تُستخدم |
| --- | --- |
| **Observable** | تحسين قابلية المراقبة اختياريًا بتغييرات محلية قليلة التدخل |
| **Integrate** | إعداد دمج debug واختيار إصدار MCP متوافق |
| **Probe** | استقصاء وقت التشغيل بلغة طبيعية من إنشاء probe حتى تحليل الأدلة |
| **Test** | إنشاء ملفات من توقعات صريحة، وتشغيل الاختبارات وتلخيص النتائج |
| **Presets** | تحويل الإجراءات واستعلامات الحالة المتكررة إلى إمكانات قابلة لإعادة الاستخدام في Probe وTest |

راجع Skills الخاصة بـ[Android](../skills/to-android-probe/SKILL.md) و[iOS](../skills/to-ios-probe/SKILL.md) للاطلاع على مسارات العمل الكاملة.

### إعادة استخدام الإمكانات عبر Presets

يجمع Presets التنقل وإجراءات الأعمال وقراءة الحالة والتغييرات المؤقتة للسلوك لخدمة Probe وTest. استخدم Skills الخاصة بـPresets على [Android](../skills/to-android-presets/SKILL.md) أو [iOS](../skills/to-ios-presets/SKILL.md).

يحدد `presets.directory` في `.meu/config.json` المجلد الأساسي، وافتراضيًا هو `.meu/presets`، مع مجلدَي `android/` و`ios/`. تحتوي كل إمكانية على `index.js` و`index.d.ts`. يصدّر `presets.entry.js` الإمكانات العامة، وينتج البناء ملف `presets.dist.js` الذي يحمّله MCP باسم `/meu/presets.js` عند الاتصال.

بعد التعديل، أعد البناء ثم الاتصال. عند توفر جهاز، يتحقق Skill من الإمكانات بتشغيلها؛ وإلا يوضح أن سلوكها لم يُتحقق منه بعد.

## مصادر الإلهام

استُلهم Mobile Easy Use من **quickjs-android** و**xLua** و**Frida**. تمثل Frida أساس التنفيذ: يعتمد Runtime المضمّن على Frida Gadget، ويستخدم MCP جسور Java وObjective-C للوصول إلى كائنات المنصة.

حزمة npm: `@agent-easy-use/mobile-easy-use`.
